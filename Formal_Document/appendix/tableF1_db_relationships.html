A. Core Relationships
Parent Table Cardinality Child Table Foreign Key On Delete Notes
users 1 → N training_sessions user_id CASCADE Each user has zero or more training sessions; deleting a user removes all their session history
users 1 → N risk_scores user_id CASCADE Periodic risk score snapshots; latest record is the current score shown on dashboard

B. Security / Audit Relationships
Parent Table Cardinality Child Table Foreign Key On Delete Notes

C. Table Inventory
Table Name Primary Model Purpose
usersUserCore identity table; stores credentials (bcrypt hash), role, department, onboarding status, and K-Means cluster assignment
scenariosScenarioTraining scenario library; OSINT-generated and manually authored MCQ questions with difficulty, category, and XP reward
threat_feed_entriesThreatFeedEntryRaw OSINT feed ingestion log; phishing URLs from Phishing.Database and AlienVault OTX with processing status
training_sessionsTrainingSessionIndividual scenario attempt records; stores answer given, correctness, response time, XP earned, and SHAP explanation snapshot
risk_scoresRiskScoreTime-series risk score snapshots; each RF model inference produces a new record enabling trend analysis
notificationsNotificationIn-app notification queue; events include score changes, mastery achievements, and manager-assigned training
token_blocklistTokenBlocklistJWT revocation store; records jti claim and revocation timestamp on logout; checked on every protected request
awareness_responsesAwarenessResponseLikert-scale security awareness survey submissions; used to compute pre/post awareness uplift percentage
sus_responsesSUSResponseSystem Usability Scale (10-item) questionnaire submissions; aggregated for usability evaluation reporting
password_reset_requestsPasswordResetRequestAdmin-mediated password-reset workflow; stores one-time token, request status, and reviewer identity

All foreign keys are enforced at the PostgreSQL level (not only at the SQLAlchemy ORM layer). Cascade behaviour follows the principle of least surprise: deleting a user removes all personal data (CASCADE), while deleting a scenario or threat entry preserves audit history (SET NULL).
