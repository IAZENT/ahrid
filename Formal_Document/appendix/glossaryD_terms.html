Three sections: D.1 Machine Learning · D.2 Cybersecurity · D.3 AHRID-Specific

D.1 Machine Learning Terms 14 entries
Term / AbbreviationDefinition
Adaptive Engine— The AHRID component that selects the next training scenario for each employee based on their current mastery scores, risk class, and K-Means archetype. It applies spaced repetition to revisit categories where accuracy falls below the mastery threshold (80%).
Cohen's Kappa (κ)Cohen (1960) A statistical measure of inter-rater agreement that accounts for chance. Values above 0.80 indicate almost perfect agreement (Landis & Koch, 1977). AHRID's classifier achieves κ = 0.8684, demonstrating reliable risk class assignment beyond random chance.
Cross-Validation (CV)k-fold CV A model evaluation technique that partitions training data into k equally-sized folds, training on k−1 folds and validating on the remaining fold, repeated k times. AHRID uses 3-fold stratified CV (mean F1-macro = 0.8604 ± 0.0094).
F1-ScoreF-measure The harmonic mean of precision and recall: F1 = 2 × (P × R) / (P + R). The macro-average F1 treats all classes equally regardless of support, making it appropriate for imbalanced datasets. AHRID achieves F1-macro = 0.889.
Forgetting CurveEbbinghaus (1885) The exponential decay of memory retention over time without reinforcement. The adaptive engine implements spaced repetition as a countermeasure: scenarios in categories where the employee has not trained for more than seven days are prioritised for re-presentation.
K-Means ClusteringMacQueen, 1967 An unsupervised learning algorithm that partitions n observations into k clusters by minimising within-cluster variance (inertia). AHRID applies k = 5 on 18 behavioural features to produce five employee archetypes, validated with silhouette score = 0.2645.
MasteryAHRID context A per-category proficiency threshold defined as ≥ 80% accuracy sustained over at least five scenario attempts in that category. Once mastered, the adaptive engine reduces frequency of that category and prioritises unmastered or recently failed categories.
MDIMean Decrease in Impurity A Random Forest feature importance metric that measures the total reduction in node impurity (Gini) contributed by splits on a given feature, averaged across all trees. MDI scores are normalised to sum to 1.0. In AHRID, overall_accuracy has the highest MDI (0.3096).
PR-AUCPrecision-Recall AUC The area under the precision-recall curve, computed using a one-vs-rest (OvR) strategy with macro averaging across all four risk classes. PR-AUC is preferred over ROC-AUC for imbalanced datasets. AHRID achieves PR-AUC = 0.9399.
Random Forest (RF)Breiman, 2001 An ensemble learning method that builds multiple decision trees on bootstrap samples and aggregates their predictions by majority vote. AHRID's classifier uses 200 trees, max_depth = 12, and class_weight = "balanced_subsample" to handle class imbalance.
SHAPSHapley Additive exPlanations A unified framework for model interpretability based on cooperative game theory Shapley values (Lundberg & Lee, 2017). SHAP assigns each feature a contribution score to individual predictions. AHRID uses TreeExplainer for efficient exact SHAP values from the RF model.
Silhouette ScoreRousseeuw, 1987 A cluster quality metric ranging from −1 to +1, where values approaching +1 indicate well-separated clusters. Computed as (b − a) / max(a, b) where a = mean intra-cluster distance and b = mean nearest-cluster distance. AHRID's k = 5 solution achieves 0.2645.
SMOTESynthetic Minority Over-sampling Technique A data augmentation technique (Chawla et al., 2002) that generates synthetic minority-class samples by interpolating between k-nearest neighbours in feature space. Applied to the AHRID training set (k = 5) to balance four risk classes from 840 to 1,636 samples.
XAIExplainable Artificial Intelligence A branch of AI concerned with making model decisions interpretable to human users. AHRID implements XAI via SHAP TreeExplainer to generate personalised explanations of risk scores, satisfying transparency requirements under IPA 2075 §7 and the GDPR right-to-explanation principle.
D.2 Cybersecurity Terms 13 entries
Term / AbbreviationDefinition
AlienVault OTXOpen Threat Exchange A community-driven threat intelligence platform that aggregates Indicators of Compromise (IoCs) including malicious URLs, IPs, and file hashes contributed by security researchers worldwide. AHRID's OSINT pipeline polls the OTX DirectConnect API for phishing pulses.
APIApplication Programming Interface A defined set of rules and protocols enabling software components to communicate. AHRID exposes a RESTful API (61 endpoints, JSON payloads) over HTTPS, consumed by the React SPA frontend. All non-public routes are protected by JWT bearer authentication.
bcrypt— A password-hashing function incorporating a work factor (cost factor) that intentionally slows computation to resist brute-force attacks. AHRID uses bcrypt with cost factor 12 via Flask-Bcrypt; the cost factor can be increased as hardware improves without rehashing existing passwords.
Compliance BudgetAHRID / IPA 2075 The proportion of training scenarios that an employee must complete within a specified review period to remain compliant with the organisation's security awareness programme. Displayed as a percentage on the employee dashboard and used by managers for reporting.
IDN / Homograph AttackInternationalised Domain Name A phishing technique that exploits visually similar Unicode characters (e.g., Cyrillic "а" vs Latin "a") to create domain names indistinguishable to the human eye. IDN encoding is a Level 3 (Advanced) difficulty signal in the OSINT difficulty classification heuristic.
IPA 2075Information Protection Act 2075 (BS) Nepal's primary data protection legislation (enacted 2018 CE / 2075 BS) governing the collection, processing, and storage of personal information. AHRID's design incorporates IPA 2075 requirements including data minimisation (§5), consent mechanisms (§8), and user transparency rights (§7).
JWTJSON Web Token · RFC 7519 A compact, URL-safe token format used to transmit claims between parties as a digitally signed JSON object. AHRID issues access tokens (15-minute expiry) and refresh tokens (30-day expiry). A server-side blocklist invalidates tokens on logout, preventing reuse within the remaining validity window.
OSINTOpen-Source Intelligence The practice of collecting and analysing information from publicly available sources. AHRID's OSINT pipeline ingests real phishing URLs from Phishing.Database and AlienVault OTX, classifies them by lure type and difficulty, and converts them into training scenarios automatically.
Phishing.Databasemitchellkrogza/Phishing.Database An open-source repository of verified phishing URLs maintained on GitHub, updated daily with new entries from multiple community sources. AHRID's threat ingestion service fetches the phishing_links_ACTIVE.txt file to supply recent, real-world phishing examples for training scenarios.
PMTProtection Motivation Theory · Rogers, 1975 A psychological model explaining how individuals respond to threatening information based on perceived threat severity, vulnerability, self-efficacy, and response efficacy. AHRID's training design applies PMT by presenting real threat examples (high perceived severity) alongside achievable protective actions (high self-efficacy cues).
RBACRole-Based Access Control An access control model that restricts system operations based on the roles assigned to individual users. AHRID implements three roles — employee, manager, and admin — enforced at the API layer via JWT role claims and route-level decorators.
Social Engineering— Psychological manipulation of individuals to perform actions or divulge confidential information. Encompasses phishing, pretexting, baiting, and vishing. AHRID's training scenarios cover eight social engineering attack categories derived from real OSINT-sourced phishing URLs and manually authored examples.
Typosquatting— A form of cyber attack that registers domain names closely resembling legitimate brands, exploiting common typing errors (e.g., gooogle.com) or character substitutions (e.g., paypa1.com). Detected by AHRID's keyword pattern matcher as a Level 1 (Obvious) difficulty signal.
D.3 AHRID-Specific Terms 8 entries
Term / AbbreviationDefinition
AHRIDAdaptive Human-Risk Intelligence Dashboard The system developed for this thesis: a full-stack web application that combines OSINT-driven scenario generation, K-Means behavioural clustering, Random Forest risk classification, SHAP explainability, and a spaced-repetition adaptive engine to deliver personalised cybersecurity awareness training.
ArchetypeK-Means cluster profile One of five behavioural profiles produced by K-Means clustering of employee training data. Each archetype captures a distinct combination of speed, accuracy, consistency, and overconfidence patterns: C0 Overconfident Clicker (n=239), C1 Cautious Learner (n=266), C2 Inconsistent Performer (n=216), C3 Resilient Defender (n=185), C4 Disengaged Completer (n=145).
Behavioural Risk ScoreBRS A composite score (0–100) produced by the Random Forest classifier, representing an employee's probability of exhibiting high-risk security behaviour. Derived from 18 behavioural features extracted from training session history. Displayed on the employee dashboard with SHAP-based explanations.
DSR / DSRMDesign Science Research Methodology The research paradigm used for this thesis (Peffers et al., 2007). DSRM produces and evaluates IT artefacts (software, models, methods) as research contributions. AHRID was developed following the six DSRM phases: problem identification, objectives, design & development, demonstration, evaluation, and communication.
SMESmall and Medium-sized Enterprise The primary target organisation type for AHRID. SMEs are defined by the European Commission as enterprises with fewer than 250 employees and annual turnover not exceeding €50 million. SMEs are disproportionately targeted by phishing attacks (APWG, 2022) yet lack dedicated security training resources.
SPASingle-Page Application A web application architecture that loads a single HTML page and dynamically updates content via JavaScript without full page reloads. AHRID's frontend is built as a React 18 SPA using Vite as the build tool, communicating with the Flask backend exclusively via REST API calls.
SUSSystem Usability Scale · Brooke, 1996 A validated 10-item Likert questionnaire producing a usability score from 0 to 100. Scores above 68 are considered above-average usability; scores above 80 indicate excellent usability. Used in AHRID's evaluation phase to assess user experience independently of task performance.
Transparency PolicyXAI disclosure The AHRID endpoint (/api/v1/eval/transparency-policy) and corresponding UI panel that disclose to employees how their risk score is computed, which features are used, what data is retained, and how to request data deletion. Required under IPA 2075 §7 and aligned with GDPR Article 22 (automated decision-making).

Entries are listed alphabetically within each section. Cross-references: terms in italics within a definition refer to other glossary entries. All acronyms are expanded on first use in the thesis body text.
