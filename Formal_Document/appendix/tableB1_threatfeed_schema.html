Table B1. ThreatFeedEntry SQLAlchemy Model — Field Schema

PostgreSQL table: threat_feed_entries · ingested by the OSINT pipeline from Phishing.Database and AlienVault OTX

Field Name Type Nullable Description
id PK Integer No Auto-incrementing primary key
url IDX String(2048) No Raw phishing URL as ingested; unique index prevents duplicate ingestion
url_hash UNIQUE String(64) No SHA-256 digest of the URL; used as the deduplication key for fast lookup
source String(64) No Feed origin: "phishing_database" or "alienvault_otx"
lure_type String(64) Yes Assigned lure category (e.g., credential_harvest, invoice_fraud); NULL if no keyword matched
threat_type String(64) Yes AlienVault OTX pulse category (e.g., malware, phishing); NULL for Phishing.Database entries
confidence_score Float Yes Feed-supplied confidence rating (0.0–1.0); used to filter low-quality entries before scenario generation
is_active Boolean No Default TRUE; set FALSE if URL is later found to be a false positive or is de-listed by feed
is_processed Boolean No Default FALSE; set TRUE once the entry has been converted into a Scenario record
raw_data JSON Yes Full original feed payload stored verbatim for audit and re-processing; schema varies by source
ingested_at IDX DateTime No UTC timestamp of first ingestion; indexed to support recency-based queries
processed_at DateTime Yes UTC timestamp when the entry was promoted to a Scenario; NULL while pending

Unique constraint on url_hash (not on url directly) avoids PostgreSQL index size limits for long URLs. The raw_data JSON column enables feed schema evolution without database migrations.
